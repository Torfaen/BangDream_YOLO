# REQ-20260429-m4-train

## 背景/目标

本阶段对应主计划 `m4_train`。当前数据集使用 5 类 YOLO 口径：

```text
0 tap
1 skill
2 flick
3 green_note
4 green_bar
```

当前本地数据集已可划分为 train/val/test。m4 的目标是建立第一版可复现训练入口，先跑通数据读取、标签格式、训练输出和模型保存链路，再根据 bad case 决定是否补充 `skill`、`flick` 样本。

## 范围

本阶段做：

- 新增 `src/bangdream_yolo/tools/train.py`。
- 使用 Ultralytics YOLOv8 读取 `data/dataset.yaml` 训练。
- 支持冒烟训练和正式训练两种参数。
- 将训练产物输出到 `runs/`，并可选复制 best 权重到 `models/`。
- 更新 README 的 m4 使用说明。

本阶段不做：

- 不接入实时推理。
- 不实现 postprocess、tracker、scheduler。
- 不自动调参或自动补标。
- 不提交 `runs/`、`models/` 里的权重和训练产物。

## 技术细节

新增命令：

```powershell
python -m bangdream_yolo.tools.train
```

默认参数面向冒烟验证：

- `--data data/dataset.yaml`
- `--model yolov8n.pt`
- `--epochs 5`
- `--imgsz 640`
- `--batch 8`
- `--project runs/train`
- `--name m4_smoke`
- `--device auto`
- `--workers 0`（Windows 冒烟训练优先稳定）

正式训练建议参数：

```powershell
python -m bangdream_yolo.tools.train `
  --model yolov8s.pt `
  --epochs 50 `
  --batch 8 `
  --name m4_green_bar_e50 `
  --copy-best models/bangdream_yolo_m4_green_bar.pt
```

实现约定：

- 训练脚本只封装 Ultralytics `YOLO(model).train(...)`，不额外发明训练框架。
- `--device auto` 时不显式传 device，让 Ultralytics 自行选择；传入 `cpu`、`0` 等值时原样转发。
- 训练脚本将 `YOLO_CONFIG_DIR` 默认指向 `.cache/ultralytics`，避免 Ultralytics 首次导入时写入受限的用户目录。
- 训练前检查 `data/dataset.yaml` 存在。
- 训练后打印 `best.pt` 路径；若提供 `--copy-best`，复制到指定路径。
- 若当前环境未安装 `ultralytics`，给出明确错误提示。

## 验收标准

- `python -m bangdream_yolo.tools.train --epochs 1 --name m4_smoke_e1` 能启动训练并读到 5 类数据。
- 训练输出目录出现在 `runs/train/<name>/`。
- 控制台能打印 best 权重路径。
- `--copy-best models/bangdream_yolo_m4_green_bar.pt` 能复制权重。
- `git status` 不出现 `runs/`、`models/` 训练产物。

## 风险与回滚

风险：

- 当前数据量较小，`skill`、`flick` 和 `green_bar` 样本偏少，模型对这些类可能不稳定。
- 首次运行可能需要下载 `yolov8n.pt` 或 `yolov8s.pt`，受网络影响。
- CPU 训练会较慢，正式训练建议使用 GPU；所选 Python 环境必须安装 CUDA 版 PyTorch，`torch.cuda.is_available()` 才会为 true。

回滚：

- m4 改动限定在 `tools/train.py`、README 和本 REQ。
- 训练产物均在 `runs/`、`models/`，可直接删除后重跑。
